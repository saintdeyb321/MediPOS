# MediPOS — instrucciones de trabajo

MediPOS es un SaaS para boticas independientes del Perú. El backend es un monolito modular con .NET 10, ASP.NET Core, EF Core y Npgsql. PostgreSQL 18 es la fuente operacional. El frontend es una PWA React/TypeScript con Vite y TanStack Query.

- Lee [CURRENT_STATE](docs/CURRENT_STATE.md) para retomar el MVP. Consulta solo los requisitos, contratos y archivos que afecte la tarea. [SPEC](docs/SPEC.md), [ARCHITECTURE](docs/ARCHITECTURE.md) y [ADR](docs/ADR.md) son las fuentes canónicas. Los planes históricos aportan evidencia, no instrucciones vigentes. Ante diferencias entre código y contrato, identifica la discrepancia antes de cambiar reglas.
- Conserva cambios locales y limita el alcance. Respeta dependencias: Domain → SharedKernel, Application → Domain, Infrastructure → Application y API → Application/Infrastructure. Mantén reglas en dominio/aplicación, persistencia en infraestructura y HTTP en API. Reutiliza los módulos existentes.
- Autoriza desde la sesión autenticada. Valida tenant, licencia, rol, sucursal y horario cuando aplique. Conserva RLS y los permisos mínimos del runtime. Superadmin se autoriza por UUID interno en allowlist privada, separado de las membresías. El primer Owner reclama la designación con Google y correo verificado. Preserva HTTPS, Origin, CSRF y revocación.
- Usa decimal/numeric para dinero, UTC para instantes y fechas sin hora para vencimientos. Conserva atomicidad, versiones, trazabilidad y claves de idempotencia. Consulta la constancia tras una respuesta ambigua. Corrige historia financiera mediante anulaciones/reversiones auditadas. El stock cambia mediante movimientos.
- Trabaja con DEV existente (`medipos_dev`, `medipos_runtime`, HTTPS localhost:7243). Se permiten comprobaciones locales de solo lectura sobre un PostgreSQL disponible. Las pruebas que escriben, migran o ejercitan concurrencia usan un destino de pruebas aislado y autorizado, nunca la base operativa DEV. Crear recursos o ejecutar mantenimiento destructivo requiere autorización. Protege secretos y datos personales en código, pruebas, logs e índices.
- Durante desarrollo, ejecuta build y pruebas focalizadas según riesgo. Antes de un release, exige checks integrales de seguridad, arquitectura, migraciones, PostgreSQL real, frontend y aceptación manual. Reporta SHA, entorno y evidencia real, incluidos fallos y comprobaciones pendientes.
- El MVP excluye diagnóstico, sustitución terapéutica, ERP general y offline ilimitado. Mantén SUNAT/CPE separado del POS e inventario. Una nueva pieza de infraestructura requiere necesidad demostrada y ADR aprobado. Cualquier herramienta que genere instrucciones para agentes requiere revisión antes de editar estos archivos.
